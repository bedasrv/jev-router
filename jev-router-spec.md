# jev-router — a Jev-driven routing plugin for OmniRoute

**Status: v2.0 draft, 2026-10-14. P0 done on a local fork (patch built and tested, §2/§9); the plugin itself is not written.** Replaces the standalone-gateway spec v1.25 (kept whole at `docs/archive/spec-v1.25.md`; `§N` below with the prefix `A§` points into it). `[owner]` = decision already given. `[confirm]` = overturns an earlier owner decision or needs a new owner call. Verified facts carry their check date (2026-10-14 unless noted). Secrets never enter this repo; variables are referred to by name only (`~/.config/warslop/dev-secrets.env`).

## 1. What this is

Warslop calls **OmniRoute** with model `free` or `paid`. A jev-router **plugin inside OmniRoute** asks **Jev** which specialist fits the turn, and hands OmniRoute an **ordered list of explicit model ids**; OmniRoute executes them as a priority fallback and owns everything else (accounts, cooldowns, breakers, usage). jev-router is *only* the choice: it does not proxy, buffer, rewrite responses, keep billing state, translate reasoning effort or run a harness `[owner, A§1 scope rule]`.

```
warslop ──(model=free|paid)──> OmniRoute ──onRoute hook──> jev-router plugin ──> Jev (ocfree → ocpaid → openrouter)
                                  │  <── ordered ids [paid…, free…] ──────────┘
                                  └──> ephemeral priority combo ──> ocpaid | ocfree | openrouter | mscopilot
```

Shape learned from `thinkany-ai/autojev` (hand-listed candidate routes, Jev decides once per fresh user task on a bounded excerpt, confidence < 0.5 falls back to a fixed order, session stickiness). Not copied: `gargpratyush/jev-router` (a CLI wrapper, no gateway). The v1 score index (AA + OpenRouter benchmarks, SQLite, Pareto fronts, scoring weights, pool-sync daemon, Go quota ledger, admin API, Rust service) is **dropped**: the real pool is ~21 paid and ~12 free ids, selected by rules over OmniRoute's live catalog (§4).

**Fail-open by design.** If the plugin errors, answers garbage, times out, dies or is absent, the request falls through to a stored combo named `free`/`paid` (tested: plugin throws → the stored combo serves; with no stored combo the client gets `400 Unable to determine provider`). **Today's stored `free`/`paid` combos are not usable as the degraded mode**: they are `isActive:false` and still carry pre-B5 ids (`opencode/deepseek-v4.1-flash` with `providerId: ocpaid`; `deepseek-v4.1-flash` now returns 402, §6). P1 recreates both with working ids from different failure domains (§4).

### Owner decisions this overturns `[confirm]`
- **D8 (Rust/axum/distroless service, A§4)** — superseded: a plugin runs as a Node child process of OmniRoute; the deployable image is **patched OmniRoute**, not a Rust binary.
- **A§6.4 item 3 "combos are not on the request path"** — reversed: the returned list becomes a temporary priority combo (OmniRoute does the hops). Consequences measured in P0 (§9): the patch sets `maxRetries: 0` on the temporary combo, hops must cross connections, and one failure can cool a whole connection (§4 failure domains, §6). `comboCooldownWait` (`enabled:true`) turned out *not* to cause the stall I expected; its effect with an all-cooling combo is still unmeasured.
- **D1 (paid→free spill) is kept**: the paid list is `[paid candidates…, free candidates…]`.
- Plugin form itself is a proposal: the v1.25 standalone gateway is the documented fallback (§9).

## 2. The patch (the only change to OmniRoute) — built, `omniroute-jev/patches/0001-*.patch`

OmniRoute v3.8.51 (`c1e30b7`) has no hook that can both reach the network and choose the model: T09 pre-request hooks run before resolution but in a no-network vm sandbox; plugin `onRequest` runs inside `handleChatCore` after the model/provider are resolved. The patch (10 files, +293 lines of which 160 are tests; local branch `jev/onroute` in `~/src/omniroute-jev/upstream`, not pushed anywhere) adds **`onRoute`**:
- `hooks.ts`/`manifest.ts`/`manager.ts`/`sdk.ts`/`index.ts`: new event, manifest flag, `runOnRoute()` (priority order, first non-empty `string[]` wins, errors skipped).
- `loader.ts`: wrapper like `onRequest`, with `onRoute` timeout **5 s** (`OMNIROUTE_PLUGIN_ONROUTE_TIMEOUT_MS`), and **fail-fast when the plugin child is dead** (see P0 3).
- `chat.ts` + `chat/pluginOnRoute.ts`: one call just before `resolveAutoRoutingState`/`getComboForModel`; the returned ids (deduped, ≤ 12) become an in-memory priority combo named after the requested model, `config.maxRetries: 0` (the default same-model retry waited 2 s per dead member). It rides the existing combo path, so per-target connection selection, cooldowns and key policy apply unchanged.
- **Key policy:** a combo the key may use vouches for its members (OmniRoute semantics, same as a stored combo), so `allowedModels` is checked against the *requested* id (`paid`), not the plugin's picks; the helper additionally drops any pick matching the key's `blockedModels` (explicit deny always wins; tested). `reconcileGuardrailReroute` is not used.
- Upstream issue/PR in parallel; if merged the patch drops out (§8).

## 3. Routing logic (all of it lives in the plugin)

1. **When it acts.** Only for requested model `free` or `paid`; any other model passes untouched (no latency added). Hook budget: on timeout OmniRoute SIGTERM→SIGKILLs the plugin (10 s generic; the patch makes `onRoute` 5 s) and **never respawns it**, so the plugin enforces its **own hard deadline of 3.5 s** (Jev 3 s + overhead) and returns nothing (fail-open) rather than reach the kill path. Recovery from a dead plugin is `POST /api/plugins/jev-stub/deactivate` then `/activate` (tested); P3 adds a watchdog that does this.
2. **Fresh task vs continuation.** If the last message is a user message (not a tool result) it is a fresh task: ask Jev. Otherwise reuse the conversation's previous pick, re-checking eligibility (a grown context may no longer fit). Conversation key = `x-omniroute-session-id` header, else hash(system + first user message); in-memory map, TTL 1 h; lost on plugin restart (accepted).
3. **Eligibility (code, not Jev), applied to the candidate set before Jev sees it:**
   - **Full window:** `estimated_input + reserve ≤ usable_window`, `usable_window = min(context_length − reserve, max_input_tokens)` when `max_input_tokens` exists (it is often smaller: `gpt-5` 400k context / 272k input; `space-bunny-free` 1,048,576 / **524,288**). `reserve` = Warslop's `max_tokens` if sent, else `min(max_completion_tokens, 16k)`. No comfort cut below the window. Unknown window = 32k floor, never assumed large. Estimate = message chars ÷ 4 (÷ 2 for the non-ASCII share), images excluded and charged a fixed allowance.
   - **Tools:** request carries `tools` → candidate `tools` must be `true`. **Vision:** request has an image → `vision` must be `true`. `null` flag = ineligible when needed.
   - **Not checked here:** account health, cooldowns, breakers, quota — OmniRoute's (A§5.4 chat-health bullet). The Go ledger is dropped; the provider's refusal is the truth and OmniRoute's cooldown handles it.
   - **No fit at all:** return the widest-window candidates and let the upstream's own size error be the answer (no synthetic `context_too_long` in v1).
4. **Jev call** (one batched call, English): `state = {ask (last user message, first 2000 chars), pool, context:{chars, has_image, uses_tools}, candidates:[{id:"c1", description}]}`, one question `model` of type `choice` (criteria = a **map** `{c1: description}`; arrays fail validation). Instruction: "Pick the specialist that can fully complete this request in one pass. Judge required reasoning, scope, ambiguity, tool use and blast radius, not requested answer length. If two fit, pick the cheaper one." Descriptions are fixed phrases with **no numbers** (price class, strengths, speed, window class `standard|large|huge context window`); one canonical option order per pool version; ≤ 12 candidates shown for paid, ≤ 8 for free (option-order bias). The effort / task / stakes questions of v1 are dropped (effort was recorded but never applied; stakes handling parked, §9).
5. **Sources** (all verified live; same `answers` shape): `ocfree` `POST {OCFREE_BASE_URL}/v1/systemone` model `jev-1.13-free` (free); `ocpaid` `POST {OCPAID_BASE_URL}/v1/systemone` Bearer `OCPAID_API_KEY` (`jev-1.13-free`); OpenRouter `POST https://openrouter.ai/api/v1/systemone` (or `/api/alpha/decisions`) Bearer `OPENROUTER_API_KEY`, `~typesafe/jev-latest` or pinned `typesafe/jev-1.13` (~15 µUSD per judgment; the tilde alias must be re-verified live in P2). Priority failover per source timeout 1.2 s; a source with 3 consecutive failures cools 10 min × 2^(n−3), cap 6 h (in-memory). Jev input limit 64k total / 32k state + longest question (docs.typesafe.ai/models) — the 2000-char excerpt stays far below; trim client-side.
6. **Confidence** from the answer's own probabilities: `(pmax − 1/n) / (1 − 1/n)` (published exact, docs.typesafe.ai/confidence). ≥ 0.5 → use Jev's pick first; < 0.5, timeout, error or malformed → configured order (§4). 0.5 is ours, uncalibrated; tune on the decision log, not vendor example numbers. Pin the Jev version once tuned (the `latest` alias shifts distributions).
7. **Output list — alternate failure domains.** OmniRoute skips the remaining targets that share a *connection* with a member that just failed (log: "marking for skip on remaining targets"; tested: `[mixed/poor, mixed/rich]` on one connection never reached `rich`), so consecutive members must sit on **different connections**; see the failure-domain rule in §4. `paid`: `[Jev pick, then eligible paid candidates in configured order]` capped at 3 paid, then up to 2 eligible free candidates (D1 spill). `free`: pick + up to 2 more free. Jev picks only inside the pool; free turns never cross into paid. mscopilot is always last in the free order (§4).
8. **Decision log** (JSONL via `file-write`, no prompt text, hashes only): time, request id, pool, ask hash, fresh/continuation, shown candidates, Jev source + latency + probabilities + confidence, guard action, returned list. Served model/provider/cost come from OmniRoute's own response headers (`x-omniroute-model`, `-provider`, `-selected-connection-id`, `-decision`, `-cost`). `x-jev-*` response headers only if `onResponse` can add them (P0 check 6).

## 4. Candidate pools (live catalog + a rules file; adding models/providers/accounts needs no code and no rebuild)

**Three layers, none compiled in.**
1. **Live catalog (OmniRoute is the registry; refreshed every ~5 min and on demand).** `GET /v1/models` already carries, for every catalog model: `context_length`, `max_input_tokens`, `max_output_tokens`, `input_modalities` (→ vision), `capabilities.tool_calling`, `pricing`, `free` (1,035 models today, 841 with a window). `GET /api/providers` and `/api/provider-nodes` give connections with `isActive`/`testStatus`; a provider with no active connection contributes no candidates. **Gap:** custom-node models (`ocpaid/*`, `ocfree/*`, `mscopilot/*`) are *not* in that listing, so `policy.json` declares generic **listing sources** `{prefix, list_url, key_file}` (any OpenAI-compatible `GET /v1/models`; **keys come from a file, not env**: the plugin child sees only `PATH HOME USER LANG LC_ALL NODE_ENV` plus `PORT HOSTNAME TZ TMPDIR` with the `env` permission — tested, container variables are invisible); a new custom provider = create the node + connection in OmniRoute and add one source line. Window overrides for such ids can also be stored in OmniRoute itself (`PATCH /api/model-capability-overrides`: `context_length`/`max_input_tokens`/`max_output_tokens`; tested: the PATCH is accepted and readable back via `GET /api/model-capability-overrides` — so overrides can live in OmniRoute and the plugin reads them — but it does **not** make custom-node ids appear in `/v1/models`, so the listing sources stay).
2. **Rules (`policy.json`, bind-mounted, hot-reloaded on mtime; an invalid file keeps the last good one and logs).** Per pool: `include` (provider prefixes / id globs), `exclude`, `allow_source` (a list that membership must also appear in — this is how the Go-catalog rule `[owner]` stays a rule: `allow_source: go-page` for `ocpaid/*`), `billing` per provider (`subscription | free | credit`; `credit` providers need an explicit `allow` — the empty Zen credit must never be reachable by a wildcard), `max_price` for per-token providers (OpenRouter paid), `free: true` = zero price or a Free listing, `denylist`, `max_shown`. New models matching the rules join the pool automatically.
3. **Overrides (per id, optional; today's hand data in §4 becomes this layer):** `order`/`rank`, `traits` (strengths text for Jev), `context_length`, `max_input_tokens`, `tools`, `vision`, `caps_source`. Defaults when absent: window from the catalog else the 32k floor, `tools`/`vision` from the catalog else `null` (ineligible only when the request needs them), description generated from price class + window class + reasoning flag, rank by price. A model with no override is therefore usable on day one, just generically described.

**Safety for auto-admitted models.** A newly matched id enters **quarantine**: it is listed in the log and `jev-router check` but not offered until one tiny completion through OmniRoute succeeds (the §6 probe rules: only ids present in a live listing, 8192 `max_tokens`, never an id a listing does not show). A failure parks it with the reason (`ModelProtocolUnsupported`, retired `:free`, …) until the next refresh. Credit/paid-per-token providers additionally need `max_price` and a provider-side spend cap (OpenRouter key limit/guardrail; D55 — the plugin keeps no ledger).

**Accounts.** The plugin never sees or names accounts: add a connection in OmniRoute (dashboard or `POST /api/providers`) and OmniRoute rotates it, applies cooldowns and breakers. jev-router only reads `connectionCount`/`activeConnectionCount` to drop providers with none.

**Many candidates, small menu.** Jev sees at most `max_shown` (12 paid / 8 free) options per request: after eligibility, keep a diverse subset (cheapest, strongest-ranked and one per price tier/provider) in a canonical order; the full pool stays in the returned fallback list. If the pool grows large enough that rank-by-price is too crude, the parked benchmark scoring (A§5) is the upgrade path.

**Failure domains (tested, §6).** OmniRoute state that one failure can poison is per **connection**: a 402 or 410 on one model blocks every model of that connection for minutes (5 min observed for 402, 24 h for the 410), and a failed member makes OmniRoute skip the remaining members on the same connection within the request. Rule: **one custom node + connection per billing/health class**, and never put models that may 402 on the connection that carries your known-good ones. Concretely `ocpaid` (one sidecar, one connection) is split into several nodes with the same `baseUrl` but different prefixes, e.g. `ocgo` (probe-verified Go ids), `ocpv` (free previews served by the Go sidecar: `longcat-2.5-preview-free`, `step-5-preview-free`, `cat-jam-free`, `big-pickle`) and `ocrisk` (Go-catalog ids that currently 402), each with its own connection; dispatch ids become `ocgo/opencode/minimax-m3` etc. The configured order alternates domains (`ocgo`, `ocfree`, `ocgo`, `openrouter`, …) so a hop always lands on a different connection.

**Tooling, not a build:** `jev-router check` (a script in the plugin dir) prints each pool, every excluded id with its reason, quarantined ids, and the generated Jev descriptions; run it after editing `policy.json`. The image is rebuilt only for an upstream OmniRoute release or a patch change, never for models, providers or accounts.

**Dispatch id shapes (verified):** `<prefix>/<upstream id>`; the sidecars' ids already start with `opencode/`, so `ocpaid/opencode/deepseek-v4.1-flash`, `ocfree/opencode/space-bunny-free`, `openrouter/<author>/<slug>[:free]` (built-in provider; `openrouter` is a reserved custom-node prefix → 400), `mscopilot/default`. A bare `opencode/<id>` resolves to the built-in `opencode-zen`, never `ocpaid`. For custom nodes `x-omniroute-provider` is the **node id** (`openai-compatible-chat-<uuid>`), not the prefix — keep a node-id→prefix map. Custom nodes expose no models in OmniRoute's `/v1/models`; ids come from the sidecars' own `GET /v1/models` (`ocpaid` needs Bearer).

**Hard rule `[owner]`: the OpenCode Zen credit balance is empty.** Route only to ids that are covered by the Go subscription or are free: **allowed = sidecar `/v1/models` ∩ (Go page "Endpoints → Model ID" table ∪ ids Zen prices as `Free`)**. ## 6. Errors and the connection-wide cooldown hazard

**Never probe or dispatch an id that is not in the sidecar's current listing.** One `410 "Model mimo-v2.5-free has been deprecated"` made OmniRoute set `rateLimitedUntil=+24 h` on the **entire connection**; every model of `ocfree` and `ocpaid` then failed in ~13 ms with the deprecated model's message. Repair: `PUT /api/providers/<connection id> {"rateLimitedUntil":null,"testStatus":"active","errorCode":null,"lastError":null}` (done, chat resumed). A `410` naming a *different* model than requested, or an instant failure with a `reset after …h` suffix, means a connection-wide cooldown — alert, do not denylist the requested id. Probes use 8192 `max_tokens` ("Reply with exactly: pong"; a 16-token budget produced a false 502 "empty response" on reasoning models).

**A 402 is the same hazard class (tested on the isolated instance, fake upstream, one connection with a 402 model `poor` and a healthy model `rich`):** the first request returned the `402` to the client without hopping to `rich`; the next returned `503 all targets were skipped by pre-dispatch filter`; a direct `rich` request got `429 … All … accounts have exhausted their quota (cached quota state, no upstream attempt; reset after 5m)` with `Retry-After: 300`, although the log called it a "model-only lockout (402, 120 s, connection stays active)". Net: **one model's 402 blocks every model on its connection for ~5 min.** On production, `ocpaid` carries both the currently-402 Go ids and the working free ones, so a single bad pick would cut off the whole sidecar. Hence: never list a model that 402s (quarantine, §4), keep risky ids on their own connection (failure domains, §4), and never probe such ids through OmniRoute (probe the sidecar directly).

With combos doing the hops, the plugin does not classify errors; OmniRoute's combo fallback does. The shapes still matter for P0/P1 tests and for the hand `denylist` in `policy.json`:

| Shape | Meaning / handling |
|---|---|
| `402`, `billing_error`, `payment_required`, `account_required`, `quota_exhausted`, `openrouter_credits`, budget `403` (`openrouter_*_budget`/`key_limit`) | quota/billing → next member |
| `429`, `rate_limited`, `429 model_cooldown` (`reset_seconds`, `retry_after`) | hop at once; OmniRoute skips that model until its `Retry-After`; never wait |
| `404 "unavailable for free…"` (OpenRouter) | retired `:free` variant → remove from `policy.json`; OmniRoute adds a 2 min `model_cooldown` |
| `5xx`, `503 provider_circuit_open`, `503 no_eligible_providers`, upstream `api_error`, `502 empty response` | provider/server fault → next member; `provider_circuit_open` skips every model of that provider |
| `ModelProtocolUnsupported` / `does not support this protocol` / `not supported for format` (400 today, 401 on older paths — match the string, not the status) | model cannot serve the chat wire → drop from `policy.json` until re-probed; not a timed cooldown |
| `401 auth_error` | OmniRoute key suspect (first hop) or a provider's accounts all dead → skip provider |
| `mscopilot` `503 refresh token rejected` (~30 s) | dead token → exclude `mscopilot/*` (HAR re-export, A§6.4) |

Not failures: content refusals; a `ocpaid/does-not-exist` returns `400 "Model is unavailable."` with **no** fall-through to another provider.

## 8. Patch repo and image (GHCR)

Repo layout: `patches/*.patch` (from a fork branch via `git format-patch`), `plugin/` (TypeScript, tests with the OmniRoute plugin test runner or `node:test`), `policy.json`, `scripts/`, `.github/workflows/`. Daily + manual workflow:
1. Resolve the latest upstream release tag (releases are ~monthly: 3.8.50 Aug 26, 3.8.51 Sep 30); skip if `ghcr.io/bedasrv/omniroute:<ver>-jev<N>` already exists.
2. Check out upstream at the tag, `git am --3way patches/*`. On failure: open an issue, stop; the previous image stays live.
3. If `git apply --reverse --check` succeeds, upstream merged it — drop the patch.
4. Run `tests/unit/plugins-*` plus our hook test; build upstream's `Dockerfile` target `runner-web`, **amd64 only** (build needs ~6 GB: fine on public-repo runners, tight on private ones); push `ghcr.io/bedasrv/omniroute:<ver>-jev<N>` with provenance attestation.
5. Deploy pins the **digest** in `~/Containers/omniroute/docker-compose.yml`; upgrades are manual (`docker compose pull && up -d`), rollback = previous digest. No `latest` in prod. Upstream is MIT; keep its LICENSE in the image.

## 10. Risks and open items

- Jev routing accuracy is unproven (the vendor says so); confidence is a peak-probability summary, not calibrated correctness.
- Patch drift: the `chat.ts` hunk sits in a 2,585-line file; CI fails loudly, never auto-merges; the image is only as fresh as the last green build.
- Plugin memory (stickiness, source cooldowns) is lost on restart; acceptable.
- Free capacity is never guaranteed (`:free` retirements, OpenRouter daily caps, WARP-pooled `ocfree` throttling at peak); mscopilot is slow (~9 s) and shared.
- Go limits are per-model monthly dollars; the first table only; a Go-limit hit is a refusal that OmniRoute hops on; watch for community-derived normalisation claims (`anomalyco/opencode` #41391) if pacing is ever revived (A§5.4 headroom).
