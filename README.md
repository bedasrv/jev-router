# jev-router

An OmniRoute plugin that picks the model for `free` / `paid` requests, plus the small upstream patch it needs and the pipeline that publishes a patched OmniRoute image.

- `jev-router-spec.md` — the design (v2.0), test results and open items.
- `plugin/` — the plugin (`onRoute` hook): `policy.example.json` → copy to `policy.json` (git-ignored; order, facts, denylist, listing sources, with your own hosts and key path), eligibility, list builder, decision log. `node --test plugin/test/*.test.mjs` (Node 24 rejects the directory form); `node plugin/check.mjs` prints the pools against the live listings.
- `patches/` — `git format-patch` output against upstream OmniRoute. Upstream v3.8.53 rewrote the plugin/hook system and natively merged the gemini-web executor fixes (DOM-driven executor, `browserLease`, `modeSelection`, `capabilities`), so the v3.8.52-era series no longer applies. Dropped: `0003`–`0006` (superseded upstream). Re-authored as one v3.8.53-native patch, `0001-plugins-onRoute-onRouteResult-v3853.patch`, keeping the same contract: the `onRoute` pre-resolution hook (the plugin picks the model list; it becomes an in-memory priority combo with `maxRetries 0`) and the `onRouteResult` hook (one-way per-attempt outcomes: HTTP status, allowlisted `classifyComboOutcome` kind, `isUsageLimitError`); route provenance on a successful plugin-routed combo — `x-omniroute-route`/`x-omniroute-attempts`, `x-router-reason`/`confidence`/`item`/`specialist`/`thinking`, `x-omniroute-context-length`/`x-omniroute-max-output-tokens` (the answering attempt's figures, never guessed) — plus the same fields in the in-band `x_omniroute` chunk when the early keepalive commits the head on `/v1/chat/completions`. Per-attempt thinking (`thinking_by_model`) and `x-router-item` are in the same patch. Verified against v3.8.53: `git am --3way` produces a tree identical to the tested one; 78/78 router/plugin unit tests, 2271/2271 combo tests, core and open-sse typechecks clean. The only changes to OmniRoute.
- `scripts/` — `latest-upstream-tag.sh`, `apply-patches.sh` (drops a patch upstream already has; exit 3 on conflict), `build-image.sh <tag> [--push]`.
- `.github/workflows/build.yml` — daily: newest upstream tag → patch → plugin tests → amd64 `runner-web` image → `ghcr.io/<owner>/omniroute:<ver>-jev<rev>` with provenance and SBOM. Conflict → issue; previous image stays live. Tags are immutable: an existing `<ver>-jev<rev>` is never pushed over (a run that finds it skips and prints its digest in the step summary); to rebuild, bump `JEV_REV`.
- `deploy/docker-compose.example.yml` — production compose, digest-pinned, plugin dir mounted.
- `plugin/ops/` — one-off OmniRoute config scripts (`register-models.py`, `recreate-combos.py`, `split-ocpaid.py`, `set-request-queue.py`), dry run by default; `apply-effort-policy.mjs` generates every model's `thinking` map from the bundled warslop effort-table/effort-policy-draft data (dead routes removed, unknown = omit; `policy.thinking_aliases` maps a connection such as `ocpaid` to the prefixes the data was measured under). `model-profiles.json` holds what Jev reads about each paid option (good_at / weak_at / cost / measured; no model names, digits, negations or references to other options, enforced by `test/profiles.test.mjs` and reported by `check.mjs`); `apply-prompt-v2.mjs <policy.json> [--out FILE] [--threshold N] [--keep-qwen]` turns a live policy into the prompt-v2 candidate (dry run by default); `jev-eval.mjs` measures Jev's picks before vs after a payload/policy change on a mixed chat/API set against a real Jev endpoint, with accuracy per confidence bucket and per threshold.
- `plugin/ops/menu.example.json` + `apply-menu.mjs <policy.json> [--menu FILE] [--write]` — UP-10c: the (model + thinking) menu Jev picks from in both pools (`policy.menu`; with it the router runs in menu mode, without it the older model + effort path). Items, native values, ranks, backups, sticky numbers, the glm cost cutoff and the specialists (off until `menu.metering`) are policy data; see spec §7.5.
- `plugin/report.mjs` — shadow-mode evaluation of Jev against the static order, plus Jev calls/outcomes/tokens/cost per UTC day (`node plugin/report.mjs plugin/decisions.jsonl`).
- `JEV_REV` — bump when `patches/` or the build changes without an upstream release (image tag `<ver>-jev<rev>`; an existing tag is never rebuilt).

Local build (needs ~12 GB free RAM and Docker): `scripts/build-image.sh v3.8.53` (`SKIP_TESTS=1` to skip `npm ci` + tests).

Updating the patch: edit in a clone of upstream on a branch, `git format-patch -1 -o patches/`, bump `JEV_REV`.
